# 本机 Unity 接入有人云实时液位

适用目标：在这台 Windows 上的 Unity 编辑器显示反应水箱的真实液位。无需购买或部署公网服务器；本机 SDK 接收程序、FastAPI 和 Unity 可以同时运行。

## 1. 先取得实时订阅能力

有人云网页能显示实时数据，不代表账号已经具备程序调用的二次开发权益。先在有人云 **扩展功能 → 功能中心 → 二次开发** 确认申请与权限，查看是否能取得 appKey / appSecret。密钥仅配置在本机，不要发到聊天或提交 Git。

官方 JSSDK 支持浏览器订阅设备变量，基础二开及相应版本可用；初始化需要 appKey / appSecret。可以用本机浏览器运行单独的 SDK 接收页面，收到指定设备、指定变量的消息后提交给本机 FastAPI。此接收页与有人云原监控网页是不同程序。

推荐链路：

```text
液位传感器 / PLC → 网关 → 有人云
                           ↓ SDK 实时订阅（由本机主动连接）
                    本机 SDK 接收程序
                           ↓ 提交读数
                    本机 FastAPI 缓存
                           ↓ http://127.0.0.1:8011/api/liquid-level
                    Unity 液位接收组件
                           ↓ SetLevelMeters
                    水箱液位平滑升降
```

如果已有高级二开，可采用本机 Java SDK 接收程序。直接使用云端 HTTP 推送则需要云端能够访问的接收地址，不能把 `127.0.0.1` 填为云端推送地址。

不要定时高频调用“历史记录最新数据”接口获取实时值。官方明确该接口不适合实时数据获取，并限制调用频率。Unity 每秒读取**本机已接收的数据缓存**与轮询云端历史接口不同。

## 2. 本次已准备的 Unity 组件

`TankLiquidCloudClient.cs` 提供后端 JSON 读取及数据校验，尚未绑定真实有人云账号或场景对象。当前场景中的液位、材质和 Q 功能继续使用原配置。

本机 JSSDK 接收页和 FastAPI 已准备在 `Tools/UsrCloudBridge`，依赖安装于 `E:\4SB\envs\youren\python.exe` 对应环境，服务端口为 8011。先按[本机接收程序说明](../../Tools/UsrCloudBridge/README.md)启动服务，在 `http://127.0.0.1:8011/` 填写密钥、设备、变量与单位并连接，然后：

1. 在 Hierarchy 选中已有的 `TankLiquid`。
2. 添加 `TankLiquidCloudClient` 组件。
3. **Tank Liquid** 指向该对象的 `TankLiquidLevel`；同一对象上可自动查找。
4. **Poll Automatically** 勾选。
5. **Api Url** 填 `http://127.0.0.1:8011/api/liquid-level`。这是本机后端约定地址，不是有人云官方接口。
6. **Request Interval** 初始设为 1 秒；请求完成后才等待下一次，不叠加请求。
7. **Maximum Data Age** 初始为 30 秒，应大于传感器实际采集与上报间隔。
8. 先启动本机接收程序和 FastAPI，再进入 Unity Play。组件会停止 Animate Demo，等待有效数据。

`127.0.0.1` 表示运行 Unity 的这台电脑。本机接收程序与 FastAPI 运行期间需要电脑保持开机、联网；使用浏览器 JSSDK 接收时还需要保持接收页运行。

## 3. 本机接口的数据约定

后端返回 JSON 对象，以下数值仅说明结构，示例时间不是可持续使用的实时数据：

```json
{
  "levelMeters": 0.8,
  "sampleUnixMs": 1792044000000,
  "valid": true
}
```

| 字段 | 要求 |
| --- | --- |
| levelMeters | 从实际内腔箱底起算的液位高度，单位为米。需要先确认传感器单位与零点 |
| sampleUnixMs | SDK 消息的原始采样/推送时间，UTC Unix 毫秒；正常设备变量消息提供 timeMs。不能用本机每次响应的当前时间替换旧数据时间 |
| valid | 后端确认该变量读数有效时才设 true；不能仅因 HTTP 请求成功就设为 true |

有人云设备变量订阅回调是 `usrsdk.addListener('cusdeviceDataPoint', {cusdeviceNos: [...]}, callback)`。根据设备编号和变量 `dataPointId` 或 `identifier` 精确选择读数。旧数据库接口中的本地记录 id 不能直接当作有人云变量 id 使用。

本机接收页检查变量消息的 `err`：非零表示异常，不能作为有效液位；官方正常消息可省略 err。将 value 转为有限数值，按真实单位和零点换算后再输出 levelMeters。例如传感器已确认以毫米表示箱底液位时，才使用 `levelMeters = value / 1000`。FastAPI 校验并缓存结果供 Unity 读取。

读取失败、无效、过期、乱序或超出内腔高度时，Unity 保留最后一次有效目标液位，并在组件 **Connection Status / Last Error** 显示原因。`HasFreshData` 可供之后的界面显示数据状态。真正有效的 0 液位仍会显示为空箱。

水面流动材质与液位数据分开运行；液位不变时水纹仍能流动。可通过设置 Flow Speed=0 暂停水纹。

## 4. 接入前仍需确认

- 账号的二次开发权限及可用 SDK；只在本机填写密钥。
- 反应水箱的设备编号、变量 dataPointId / identifier、单位、传感器零点与采集间隔。
- 一条去掉密钥的真实 SDK 变量消息，用于完成本机接收程序的字段映射。
